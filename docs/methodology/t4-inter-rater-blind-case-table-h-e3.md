## 1. 选案规则（本表如何落实协议）

1. **纳入：** 公开可得；非 Round 1/2 教科书机制 in-sample；每案可锁 T0；冷启动材料足够写完 Ledger。  
2. **排除（Coder 侧）：** 原正式 Ledger 作者；已把本案当「标准答案演示」培训过的人；缺公开源无法冷启动的案。  
3. **均衡：** ≥3 陷阱表面（产品≠专利 / 整机叙事 / 权利叙事拒抬）；≥2（本表 6）E3 候选，使 claims-check 必须在 **PASS 压力** 与 **FAIL/贴纸压力** 两边都被练习——**但不在 Coder 表上标注哪边是哪边**。  
4. **不泄漏：** Coder 包只含 §2；§F 密封键仅 Facilitator / 用户确认用，开跑交卷前禁止发给 Coder。  
5. **复用已编码案的理由：** H-E3 测的是 **新人按文档独立可操作性与双人一致**，不是再测「仓库作者能否复述自己写过的 R」。已编码案提供已知公开源密度与陷阱类型，避免冷启动因「无材料」崩掉；金标 **不** 计入主一致率（协议 §1.2 / §5）。

## 4. 成功标准（开跑前可微调，须改日期）

沿用 [`t4-inter-rater-blind-protocol-h-e3.md`](t4-inter-rater-blind-protocol-h-e3.md) §5.3：

| 门 | 阈值 |
|---|---|
| H-E3 操作未崩溃 | 可完成率 ≥ **80%**；一次 CI 绿率 ≥ **70%**（按案、两 Coder 平均） |
| 一致性「可讨论」 | R 一致率 ≥ **0.70** 且 E3 一致率 ≥ **0.70** |
| 一致性「强支持」 | 上两者均 ≥ **0.80**，且陷阱子集（HE3-02/03/04）**无**双人假抬 R3+ |
| 主失败 | 可完成率 &lt;50%，或陷阱子集双人假抬 R3+，或 E3 一致率 &lt;0.50 |

主一致率 = **裁断前** 原始标签；不把一致率写成准确率；不回写已合并 holdout（除非另批 encode PR）。
