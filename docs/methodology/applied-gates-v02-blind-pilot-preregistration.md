# 应用型评价与估值闸门 v0.2：盲法可复核试验预注册

> 2026-10-29 · **research-only** · 正式方法仍为 V0.7 / schema 1.0 · 不采用 V0.8
> v0.1来源：`docs/methodology/applied-evaluation-valuation-protocol-v0.1.md`
> **隐私边界：**用户提供的17件案例、2024评审底表、专利级收入与重新评分均不得上传到这个公开仓库。

## 1. 验证对象

测试三个相互独立的命题：

- **H-A（评分闸门）**：证据不完整、分项缺失或双人意见未复核，不能输出可用于评审决策的最终分数；证据齐备则应允许计算。
- **H-B（估值闸门）**：即使有净现金流或同业规模，没有指定权利对象、权属/权项/映射/经济归因/期限风险 G0–G4 全部核实，也不得产生研究性货币估值区间。
- **H-C（独立复核）**：在无历史得分、无申请人品牌和商业结果提示时，两名不同评审员是否能独立给出一致的**证据状态与技术判断**。不预测奖项名次或市场价格。

检索参数固定：`country_code=CN`、`kind_code=B`、`ipc_code`、`publication_date_from/to`、`page=1`、`page_size=20`。对返回的B授权公告记录去重并筛选窗口，按 `SHA256("xiangsee-v02|"+专利号)` 从小到大选择第1件；若空集合，记录失败并不私自更换行业。记录原始查询、候选数量和hash选择依据。

**限制**：搜索服务的前20条本身是排序后的便利集合，这不是概率抽样；只能作为跨领域的冷启动压力测试，不能用小样本“证明”统计意义上的准确率，也不能推定一般专利总体。

## 3. 真正双人盲审边界

公开样本由协调人建立编号 `B-01`～`B-06`；评审包不含权利人名称、历史评分、企业销售额、后续获奖情况及专利号（揭盲表另存）。

- 评委A、评委B**分别在独立工作簿填写**。不能共用公开可见的评分工作表。
- 阶段一只评审：摘要所述技术问题、独立权利要求要素、替代技术与所需证明；可标记「证据不足」。
- 若仅有摘要/专利登记，E3/E4视为 **Unknown**，不能推断为零；不得凭企业规模授予R3+。
- 两位评委提交并冻结后才揭盲和比较。绝不由同一模型模拟两个“独立评委”并报告虚假的一致性。
- 一致性指标：可判定项覆盖率；二值门槛一致率；无缺失且分类可比时计算 Cohen's κ（含样本太小 / 单一类别下不适用警告）；连续分数在双方均已合法评分时才计算差值。
- 当前只设计试验与制作评审包；**没有真实独立评委数据前，所有一致性均为 Not Run**。

## 4. 五道货币估值闸门

`G0 rights+purpose`、`G1 claim/technical`、`G2 exact link or contract-defined rights`、`G3 attributable economics`、`G4 remaining economic life/risk`。

硬规则：
- 逐闸门只有`通过`、`不通过`、`待核`；必须绑定来源标识与核查者。缺来源不可等同通过。
- 发起估值需`purpose`、`basis_of_value`、`rights_subject`、`as_of_date`；
- 只有**同一 rights_subject** 的 G0–G4 均已核，才能启动 L2 indicative range。
- L1场景演示允许研究输入，但不得称 L2“专利市值”；正式评估意见L3仍需专业机构。
- `verdict`、`product revenue`、`pledged loan amount`、`license portfolio cash`不可自动升格为 exact-patent value；
- 即使闸门通过，收益法仍需折现率、税、合同净收益、剩余期限、T0、来源完整，不得从奖项分数代入。
- **反例单测**：仅手输「通过」却无来源；G3被否；rights_subject不一致；历史分高却缺现金流；判赔≠收款；许可应收款出售对价不重复加。

## 5. 验收与升级边界

本轮只在应用层新增：
- 公开可复核的验证脚本与虚构 fixtures；
- 六件新公开专利的盲审任务包；
- 内部17件数据的本地闸门修复工作簿；
- 一致性对照工具和诚实的`Not Run`状态。

本轮不得：把历史评审分数当真实价值标签、向公共仓库上传用户案例、修改正式V0.7、不经授权升格V0.8、输出未经证实的货币价值。
